## Purpose

This note records the first annotation protocol for disaster-related change detection data. It turns the earlier dataset study into a repeatable screening and annotation workflow.

## Selection Criteria

| Criterion | Reason |
| --- | --- |
| Pre-event and post-event pairing | The images must represent a meaningful before/after comparison. |
| Cloud and haze screening | Atmospheric artifacts can create false change evidence. |
| Visual alignment | Poor registration can produce boundary errors unrelated to the disaster. |
| Clear change target | Candidate tiles should contain interpretable changed and unchanged areas. |
| Reusable metadata | The source, time window, and screening decision should be traceable without exposing private paths. |

## Annotation Convention

| Label | Meaning |
| --- | --- |
| Changed | Areas where the visible land-cover or structure change is part of the target event or selected change process. |
| Unchanged | Areas that remain stable or are outside the defined change target. |
| Review | Ambiguous boundaries, cloud-affected regions, or uncertain alignment cases that need later checking. |

## Quality-Control Notes

The Phase I protocol keeps the target binary because the current FYP benchmark is binary change detection. The main quality risks are cloud cover, seasonal variation, misregistration, and ambiguous event boundaries. These issues are recorded before expanding annotation volume so the final dataset work can stay consistent.
