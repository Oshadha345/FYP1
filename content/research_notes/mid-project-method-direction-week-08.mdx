## Review Summary

The first half of the project established the problem framing, dataset assumptions, benchmark protocol, baseline evaluation workflow, and disaster-data annotation protocol. The review step connected these pieces into a second-half plan.

## Direction Selected

| Decision | Rationale |
| --- | --- |
| Keep binary change detection as the main scope. | It matches the current benchmark protocol and avoids expanding into semantic change categories too early. |
| Prioritise boundary-aware behaviour. | Week 5 and Week 6 made boundary metrics and qualitative edge errors central to evaluation. |
| Design the model in stages. | Encoder comparison, temporal feature comparison, refinement, loss design, and training should remain separable. |
| Preserve disaster-data caution. | Annotation noise and domain shift can affect later claims if they are not tracked from the start. |

## Deferred Alternatives

| Alternative | Reason for deferral |
| --- | --- |
| Full semantic change detection | It would require a different annotation target and evaluation setup. |
| Generative mask modelling | Useful literature direction, but not the first implementation priority. |
| Large disaster dataset expansion | Annotation consistency needs to be stabilised before scale. |

## Output

The review produced the Week 9-14 direction: binary model design, region-boundary refinement, decoder and loss design, benchmark training, controlled evaluation, and final documentation.
