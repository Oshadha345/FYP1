## Refinement Design

| Stage | Role |
| --- | --- |
| Base prediction input | The module starts from the binary change map produced by the Week 9 design path. |
| Feature input | Decoder or multiscale features provide local detail that the coarse prediction may not preserve. |
| Region reasoning | The region path supports coherent changed and unchanged areas. |
| Boundary reasoning | The boundary path focuses on edge alignment, thin structures, and noisy mask borders. |
| Output combination | The refined output is treated as a corrected binary prediction, with quantitative contribution reserved for later controlled evaluation. |

## Decisions

| Decision | Reason |
| --- | --- |
| Keep refinement separate from the base binary model. | This makes later ablation easier and keeps the Week 9 model design clear. |
| Treat region and boundary evidence as related but not identical. | Region metrics and boundary metrics measure different failure modes. |
| Use boundary-aware evaluation before claiming improvement. | A refinement module should be judged with both mask-level and edge-level measures. |
| Defer final loss design to Week 11. | Auxiliary supervision and loss balancing need a separate design step. |

## Technical Challenge

| Challenge | Resolution direction |
| --- | --- |
| Refinement can over-correct noisy predictions. | Keep the refined output tied to the original binary prediction and verify behaviour qualitatively before ablation. |
| Boundary emphasis can damage region consistency. | Evaluate region metrics and boundary metrics together rather than optimising one in isolation. |
| Thin structures are easy to remove during decoding. | Preserve multiscale local detail for the refinement stage. |
