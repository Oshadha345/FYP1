## Goals for the Week

| Goal | Result |
| --- | --- |
| Analyse baseline predictions after the Week 5 evaluation setup. | Completed using the DSIFN-CD and WHU-CD baseline evaluation workflow. |
| Separate region-level errors from boundary-level errors. | Completed by using Precision, Recall, F1-score, IoU, Boundary F1, and Boundary IoU as the organising measures. |
| Identify failure categories that should influence later model design. | Completed as a qualitative error taxonomy for the next design stages. |
| Keep detailed benchmark values private until controlled reporting. | Completed; numerical tables remained in the internal experiment material. |

## Tasks Completed

| Task | Output |
| --- | --- |
| Reviewed baseline failure modes from the Week 5 evaluation setup. | Error categories were grouped around false alarms, missed changes, boundary displacement, and dataset-specific behaviour. |
| Compared region and boundary interpretations. | Region metrics were kept for mask-level quality, while boundary metrics were used to inspect edge alignment. |
| Checked dataset-specific concerns. | DSIFN-CD and WHU-CD were treated separately because their scene content and annotation conventions can stress the model differently. |
| Prepared a public analysis record. | [Baseline error analysis note](/notes/baseline-error-analysis-week-06) summarises the workflow without publishing private scores. |

## Findings

| Area | Observation |
| --- | --- |
| Region errors | False positives and missed changed regions need to be tracked separately because they imply different model weaknesses. |
| Boundary errors | Boundary F1 and Boundary IoU are useful because ordinary IoU can hide small edge displacements. |
| Thin and small structures | Small changed objects and narrow structures remain important because a few missed pixels can affect visual usefulness. |
| Dataset behaviour | DSIFN-CD and WHU-CD should not be interpreted as interchangeable because their scenes and mask conventions differ. |
| Domain shift | Illumination, registration, and spatial-resolution differences need to be treated as possible sources of false change evidence. |

## Decisions

| Decision | Reason |
| --- | --- |
| Keep both region and boundary metrics in later evaluation. | Region metrics report mask overlap, while boundary metrics preserve edge-quality information. |
| Use qualitative inspection before adding model complexity. | A refinement module should respond to observed boundary and small-change issues, not only to aggregate metrics. |
| Avoid publishing exact baseline tables here. | The public portfolio can describe method and interpretation while leaving detailed values for controlled reporting. |

## Technical Challenge

| Challenge | Resolution direction |
| --- | --- |
| Boundary displacement is difficult to interpret from a single score. | Use Boundary F1 and Boundary IoU together with visual inspection of predicted masks. |
| Dataset shift can look like real change. | Treat illumination, registration, and scene-source differences as separate qualitative categories. |
