## Dates

15/06/2026 - 21/06/2026

## Goals for the Week

| Goal | Result |
| --- | --- |
| Review progress from Weeks 1-7. | Completed by summarising literature, dataset planning, benchmark setup, baseline evaluation, and annotation Phase I. |
| Select the technical focus for the second half of FYP1. | Completed with boundary-aware binary change detection kept as the main direction. |
| Identify which alternatives should not be prioritised immediately. | Completed by deferring semantic change detection, generative mask modelling, and broad dataset expansion. |
| Define implementation priorities for Weeks 9-14. | Completed as a staged path from model design to refinement, loss design, training, evaluation, and documentation. |

## Work Reviewed

| Area | Review outcome |
| --- | --- |
| Literature | CNN, Transformer, diffusion, and state-space model directions were already mapped through paper notes and the literature matrix. |
| Benchmark setup | The first controlled benchmark needed consistent datasets, metrics, and experiment tracking before model claims. |
| Boundary analysis | Week 6 made boundary quality and small-change behaviour central to later design. |
| Disaster data | Week 7 clarified that annotation consistency and data quality are project risks, not only data-collection tasks. |

## Decisions

| Decision | Reason |
| --- | --- |
| Keep the next model stage binary rather than semantic. | Binary change detection gives a cleaner evaluation target for the current FYP1 scope. |
| Prioritise bitemporal feature comparison and boundary-aware refinement. | Earlier work showed that both change evidence and boundary quality need explicit attention. |
| Use existing literature notes as design references. | ChangeFormer, GLMamba, consistency regularization, and local precision-fusion work cover the main design pressures. |
| Defer final loss and training decisions to later weeks. | Architecture, refinement, and loss design should be separated so each decision can be evaluated clearly. |

## Technical Direction

| Priority | Direction |
| --- | --- |
| Model structure | Design a bitemporal binary change detection model with shared feature extraction and explicit temporal comparison. |
| Decoder behaviour | Produce a binary change map while preserving multiscale spatial detail. |
| Refinement | Add a region-boundary refinement stage after the baseline binary prediction design. |
| Evaluation | Keep region metrics, boundary metrics, and qualitative inspection together. |

## Risks and Constraints

| Risk | Mitigation |
| --- | --- |
| Boundary refinement could add complexity without clear evaluation value. | Keep later ablations controlled and report boundary metrics separately. |
| Disaster annotation can introduce label noise. | Keep the annotation protocol explicit and review ambiguous regions before using them for conclusions. |
| Model-family comparisons can become unfair. | Preserve consistent dataset, crop, and metric settings across experiments. |
