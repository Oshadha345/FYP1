## Goals for the Week

| Goal | Result |
| --- | --- |
| Convert earlier disaster-data planning into an annotation workflow. | Completed as an initial Phase I protocol. |
| Define how pre-event and post-event image pairs should be screened. | Completed with criteria for temporal pairing, cloud impact, alignment, and scene relevance. |
| Clarify binary mask conventions for disaster-related change. | Completed at protocol level before expanding annotation volume. |
| Record quality-control concerns for later dataset work. | Completed with checks for registration, ambiguous boundaries, seasonal changes, and no-change regions. |

## Tasks Completed

| Task | Output |
| --- | --- |
| Reviewed imagery-source assumptions from Week 2. | Google Earth Engine and Sentinel imagery remained the practical starting point for disaster-data exploration. |
| Defined sample-selection criteria. | Candidate pairs were organised around before/after timing, cloud screening, visible change evidence, and geographic consistency. |
| Specified mask conventions. | The first protocol used a binary changed/unchanged interpretation suitable for controlled change detection. |
| Documented annotation risks. | Ambiguous damage boundaries, seasonal appearance changes, and image registration error were treated as quality-control issues. |

## Work Performed

| Area | Description |
| --- | --- |
| Imagery source | The workflow built on the Week 2 decision to use accessible satellite imagery and Google Earth Engine for early exploration. |
| Pair selection | Pre-event and post-event images were screened for clear temporal relation and usable visual quality. |
| Annotation target | The mask target was kept binary so the data could support the first controlled benchmark and later model evaluation. |
| Quality control | The protocol separated true disaster-related change from cloud cover, seasonal vegetation change, misregistration, and low-confidence edges. |

## Decisions

| Decision | Reason |
| --- | --- |
| Keep Phase I focused on workflow and conventions. | A small but consistent protocol is more useful than a larger inconsistent annotation set. |
| Use binary masks first. | The FYP benchmark and model design are centred on binary change detection. |
| Preserve uncertainty in ambiguous areas. | Disaster scenes can contain soft or partially visible boundaries that should not be forced into overconfident labels. |

## Technical Challenge

| Challenge | Resolution direction |
| --- | --- |
| Clouds and seasonal differences can be mistaken for damage. | Screen candidate pairs before annotation and record low-confidence cases. |
| Pre-event and post-event images may not align perfectly. | Treat alignment as a quality-control condition before using a pair for model evaluation. |
| Disaster boundaries can be visually ambiguous. | Use consistent mask rules and mark uncertain cases for later review. |
