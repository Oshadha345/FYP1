## Goals for the Week

| Goal | Result |
| --- | --- |
| Translate the Week 8 method direction into a binary model design. | Completed as a public high-level architecture plan. |
| Define how the two temporal images are processed. | Completed with shared bitemporal feature extraction as the main design assumption. |
| Specify temporal comparison and decoding responsibilities. | Completed by separating feature comparison, multiscale fusion, and binary mask prediction. |
| Identify which parts should move to Week 10 and Week 11. | Completed by deferring boundary refinement, decoder-head details, and loss design. |

## Model Design

| Component | Design role |
| --- | --- |
| Bitemporal input | The model receives aligned pre-event and post-event images as the paired input. |
| Shared encoder | A shared feature extractor keeps the two temporal branches comparable and follows the Siamese change detection pattern. |
| Temporal comparison | Feature differences and fused bitemporal features represent candidate change evidence. |
| Multiscale handling | Features from more than one spatial scale are kept available so the decoder can combine context with local detail. |
| Binary decoder | The decoder produces a binary change map rather than a semantic class map. |
| Refinement hand-off | Boundary-focused correction is separated into the Week 10 refinement stage. |

## Decisions

| Decision | Reason |
| --- | --- |
| Use a Siamese-style shared encoder at design level. | It fits bitemporal remote sensing inputs and is supported by the ChangeFormer and Liquid Siamese literature notes. |
| Keep explicit temporal comparison in the design. | Earlier notes on feature differences and latent differences show that change evidence should not be left entirely implicit. |
| Preserve multiscale features for the decoder. | Boundary quality and small objects require local detail as well as scene-level context. |
| Keep the first output binary. | The project scope and evaluation protocol are centred on binary change masks. |

## Technical Constraints

| Constraint | Handling |
| --- | --- |
| Public description cannot expose private architecture sketches. | The page records module responsibilities and interfaces rather than unpublished implementation details. |
| Dataset shift may affect feature differences. | The design keeps qualitative inspection and domain-shift analysis as part of evaluation. |
| Boundary errors need a later correction stage. | Region-boundary refinement is deferred to Week 10 instead of mixing it into the base model description. |
